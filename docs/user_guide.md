# OpenWire User Guide

This guide describes how to integrate the OpenWire core `owr_core` into an FPGA design: sources, generics, clocks,
interfaces, the connection to the line drivers and receivers, the protection scope, the programming sequence, the
performance, the integration constraints, the conformance to the standard and the corrected defects. The architecture
is described in [architecture.md](architecture.md), the registers in the generated
[register map](../hdl/owr_mib/docs/register_map.md).

## 1. Sources

| Library | Sources | Order |
| --- | --- | --- |
| `olo` | Open Logic areas `base`, `axi`, `intf` and `ft` of the submodule `open-logic/` | `open-logic/compile_order.txt` |
| `openwire` | `hdl/<module>/src/*.vhd` of every module of `component_list.txt` | `compile_order.txt` (generated by `python run.py --compile-order`, checked by the CI) |

All sources are VHDL-2008 and contain no vendor primitive. `tools/synth_vivado.py` shows a complete source list and
the clock constraints for AMD Vivado.

## 2. Generics

| Generic | Default | Range | Description |
| --- | --- | --- | --- |
| `LinkClkFreq_g` | 100.0e6 | 18 to 22 MHz, 27 to 33 MHz, 36 to 44 MHz, 45 to 2554 MHz | Frequency of `LinkClk` in Hz. The range follows from 10 Mb/s +/- 10 % with an integer divider, from the receiver, which samples the initial rate of the far end (at most 11 Mb/s) with at least 1.2 `LinkClk` periods per bit, and from the 8-bit field LINK_SPEED.INIT_DIV. Elaboration stops outside it |
| `TxFifoDepth_g` | 64 | Powers of 2, 2 to 32768 | Depth of the transmit FIFO in N-Chars. Elaboration stops outside the range |
| `RxFifoDepth_g` | 64 | Powers of 2, 16 to 32768 | Depth of the receive FIFO in N-Chars: room for the eight N-Chars of an FCT and the reserved place of an EEP. 64 or more allows seven outstanding FCTs (56 N-Chars). Elaboration stops outside the range |
| `TimeCodes_g`, `Interrupts_g` | true | boolean | Time-code service and distributed interrupt service, in any combination |
| `IntTimerWidth_g` | 16 | 1 to 30 | Width of the minimum interval and acknowledgement delay of the interrupt service, in ticks |
| `LinkDisabled_g`, `LinkStart_g`, `AutoStart_g` | false | boolean | Reset values of LinkDisabled, LinkStart and AutoStart: a port with `LinkStart_g` or `AutoStart_g` starts the link without software |
| `RunDiv_g` | 1 | 1 to 255 | Reset value of the bit period in the Run state in `LinkClk` cycles |
| `SyncStages_g` | 2 | 2 to 4 | Synchroniser stages of data and strobe |

Every value of a boolean generic is simulated, and the bounds of every range are elaborated and synthesised; the
[verification report of `owr_core`](../hdl/owr_core/docs/verification_report.md) lists the values.

## 3. Clocks and reset

| Clock | Function | Requirement |
| --- | --- | --- |
| `LinkClk` | Encoding and Data Link layers, Network layer functions, register file | Transmit bit period = n `LinkClk` periods (n = 1 to 255). The receiver samples data and strobe once per period: the far end's bit period, reduced by its skew and jitter, must be longer than one `LinkClk` period |
| `UserClk` | Packet and broadcast service ports | Any frequency |
| `MgmtClk` | AXI4-Lite port and `Irq` | Any frequency |

The three clocks may be the same clock. `Rst` is an asynchronous high-active reset; the core synchronises its release
in each domain. Every crossing between the domains is an Open Logic FT FIFO or synchroniser. Constrain each pair of
different clocks in both directions with `set_max_delay -datapath_only` and the period of the faster clock, as the
Open Logic clock crossing principles describe; in Vivado the scoped constraints of the Open Logic crossings add the
bus skew limits. Do not declare the clocks as asynchronous clock groups: `set_clock_groups -asynchronous` overrides
these delay constraints.

| `LinkClk` | Initial rate | Fastest transmit rate (divider 1) | Fastest receive rate (bit period > 1.2 periods) |
| --- | --- | --- | --- |
| 50 MHz | 10 Mb/s | 50 Mb/s | about 41 Mb/s |
| 100 MHz | 10 Mb/s | 100 Mb/s | about 83 Mb/s |
| 125 MHz | 9.6 Mb/s | 125 Mb/s | about 104 Mb/s |
| 200 MHz | 10 Mb/s | 200 Mb/s | about 166 Mb/s |

The run divider must be chosen for the far end: a port must not send faster than the far end can sample.

## 4. Interfaces

### 4.1 Packet ports (`UserClk`)

`S_Pkt_*` and `M_Pkt_*` are AXI4-Stream ports with one N-Char per beat: a beat with `TLast` = '0' carries a data byte,
a beat with `TLast` = '1' is the end of packet marker and carries no data byte (`TData(0)` = '0' EOP, '1' EEP; the
receive port delivers 0x00 or 0x01). A packet of n bytes is n + 1 beats; a packet without data is a single marker
beat. A packet received with an error (link error in the middle of a packet, ECSS 5.5.8.4) ends with an EEP.

### 4.2 Broadcast services (`UserClk`)

| Port | Width | Service |
| --- | --- | --- |
| `S_Tc_*`, `M_Tc_*` | 6 | TIME-CODE.request, TIME-CODE.indication of valid time-codes |
| `S_Int_*`, `M_Int_*` | 5 | DISTRIBUTED_INTERRUPT.request and .indication |
| `S_IntAck_*`, `M_IntAck_*` | 5 | DISTRIBUTED_INTERRUPT_ACK.request and .indication |

Requests are AXI4-Stream transfers. The indication ports have a ready input (default '1'); an indication is
discarded and EVENTS.IND_OVERFLOW set when the indication FIFO (16 entries) is full. The same requests are available
through the MIB (TC_SEND, INT_SEND, INT_ACK).

The distributed interrupt service needs the timing of the network (ECSS 5.6.5.4c, d and 5.6.5.6e): INT_HOLDOFF is
the minimum interval between two interrupt codes of one identifier (longer than the propagation of an interrupt code
across the network, plus the acknowledgement time in interrupt with acknowledgement mode), INT_ACK_DELAY the minimum
delay before an acknowledgement code (longer than the propagation of the interrupt code). Both count ticks of
INT_TICK cycles (1 us after reset) and are zero after reset; set them for the network before using interrupts.

### 4.3 MIB (`MgmtClk`)

AXI4-Lite with 8-bit byte addresses and 32-bit data. Registers are written as 32-bit words. AXI4-Lite does not order
a read against an earlier write on the other channel: wait for the write response before reading a value that
depends on it. `Irq` is the OR of the error and event flags enabled in ERRORS_IRQ_EN and EVENTS_IRQ_EN.

### 4.4 Line drivers and receivers (`LinkClk`)

`Spw_DOut` and `Spw_SOut` come from flip-flops and change in the same clock edge, never together. `Spw_DIn` and
`Spw_SIn` are asynchronous; they enter a triplicated synchroniser. `Phy_TxEn` (PORT_CTRL.DRIVER_EN) can drive the output
enable of a tri-state LVDS buffer, `Phy_RxEn` (PORT_CTRL.RECEIVER_EN) the enable of the input buffer. The I/O buffers
belong to the design that integrates the core; section 8 lists what the target provides.

The minimum tolerated separation between edges at the receiver (MinsepIN, ECSS 5.3.7.2j) is one `LinkClk` period plus
the setup and hold window of the input flip-flops.

## 5. Protection scope

The core is designed for radiation environments together with the triple modular redundancy (TMR) of the synthesis
tool, like the Open Logic ft entities it is built on. It protects the parts in the first rows itself and relies on
TMR for all other logic:

| Part | Protection | Indication and test |
| --- | --- | --- |
| FIFOs: transmit, receive, broadcast requests, broadcast indications, register requests, register responses (EDAC channels 0 to 5) | SECDED ECC of the Open Logic ft entities: a single error is corrected, a double error is detected and contained (see below) | EVENTS.ECC_SEC, EVENTS.ECC_DED, ECC_STATUS, ECC_COUNT, `Irq` through EVENTS_IRQ_EN; error injection through the ECC_INJECT register |
| Clock domain crossings and reset synchronisers, data and strobe inputs | Triplicated synchronisers (`SyncTmr_g` = true): three synchroniser chains and a majority voter. Their registers carry the Synplify attribute `syn_radhardlevel` = `none`, so the TMR of the synthesis tool adds no voters between the stages. The event crossing `owr_cc_pulse` also triplicates its request, pending and last registers | none |
| State machines | Recovery state through the `when others` branch and the reset; the link state machine and the link error recovery also through the port reset (PORT_CTRL.PORT_RESET) | none |
| All other logic: registers of the control and data paths, counters, pointers, pipeline registers | TMR of the synthesis tool (for example `syn_radhardlevel` = `tmr` with Synplify, or the equivalent setting of the tool chain). The core adds no protection of its own for this logic; without TMR, an upset in it is not covered | synthesis report |

A double error is never passed on as valid data: an N-Char read from the transmit FIFO is sent as an EEP and the rest
of the packet is discarded; an N-Char read from the receive FIFO is delivered as an EEP and the rest of the packet is
discarded; a broadcast request or indication is discarded; a register request or response is dropped, and the
read then ends with SLVERR after the read timeout of the AXI4-Lite slave. ECC_INJECT writes a single or a double
error into the next word of a FIFO for tests of the software.

The integrator:

- enables the TMR of the synthesis tool for the core and the logic around it,
- checks in the synthesis report that TMR was applied, that the synchroniser chains of the crossings were not
  triplicated a second time, and that no register-based storage meant to be protected by TMR was inferred as a RAM
  primitive,
- requests safe state machines, so that synthesis keeps the `when others` branches (AMD Vivado: property
  `FSM_SAFE_STATE` = `default_state` on the state registers; Synplify: attribute `syn_encoding` = `safe`),
- protects the configuration memory of SRAM-based FPGAs by scrubbing; this is part of the FPGA design, not of the
  core.

The ECC paths are verified in simulation by error injection. Whether the protection as a whole meets the
requirements of a mission is shown by a radiation test with the core in operation (TRL 5).

## 6. Programming sequence

After reset the port is in ErrorReset or Ready according to the generics. A typical start by software:

1. Read ID (0x4F575201) and GENERICS.
2. Write LINK_SPEED.RUN_DIV with the bit period for the Run state.
3. Optionally enable interrupts: EVENTS_IRQ_EN.LINK_UP, ERRORS_IRQ_EN.
4. Write PORT_CTRL: LINK_START (or AUTO_START to wait for the far end) with DRIVER_EN and RECEIVER_EN.
5. Wait for PORT_STATUS.LINK_STATE = 5 (Run) or the LINK_UP event.
6. Exchange packets on the packet ports.

A link error (disconnect, parity, ESC or credit error) restarts the link automatically: PORT_STATUS.LAST_CAUSE, ERRORS
and the counters record it; the packet being received ends with an EEP, the rest of the packet being sent is
discarded. PORT_CTRL.PORT_RESET clears both FIFOs and restarts the link; PORT_CTRL.LINK_DISABLED stops it.

## 7. Performance

The rates hold for each direction of the link. R is the data signalling rate on the line in bit/s.

### 7.1 Link

| Item | Value | Evidence |
| --- | --- | --- |
| Transmit data signalling rate | R = f(`LinkClk`) / LINK_SPEED.RUN_DIV in the Run state (RUN_DIV = 1 to 255); 10 Mb/s with the initial divider outside Run | TC-EN-01, TC-EN-03 |
| Receive data signalling rate | The bit period of the far end, reduced by its skew and jitter, is longer than one `LinkClk` period (section 3); verified down to 1.2 `LinkClk` periods | TC-EN-16 |
| Characters on the line | Data character 10 bits; EOP, EEP and FCT 4 bits; Null 8 bits; time-code, interrupt code and acknowledgement code 14 bits each (ECSS 5.4.3) | TC-EN-02 |
| Sending order | Broadcast code, FCT, N-Char, Null (ECSS 5.5.6); the characters follow each other without idle bit periods | TC-DL-20, TC-DL-40 |
| Flow control | One FCT on the line for every 8 N-Chars received from the far end; up to seven FCTs (56 N-Chars) outstanding with a receive FIFO of 64 or more | TC-DL-10, TC-DL-11 |

A packet of n bytes takes n data characters and one end of packet marker on the line. Its user data rate is

```text
P = 8n / (10n + 4) * (R - Nrx / 2 - 14 * Btx)
```

with Nrx the N-Chars per second that the port receives from the far end (each costs half a bit of FCT on this line)
and Btx the broadcast codes per second that the port sends.

| Case | Formula | Value | Simulation |
| --- | --- | --- | --- |
| One direction | 8n / (10n + 4) * R | 79.97 Mb/s for n = 1000 at 100 Mb/s | 79.96 Mb/s (TC-DL-40) |
| Both directions, same n and R | 8n / (10.5n + 4.5) * R | 76.2 Mb/s for n = 1000 at 100 Mb/s | none |
| A: n = 1000 at 100 Mb/s; B: n = 600 at 62.5 Mb/s, at the same time | P of A and B with each other's Nrx | A 77.7 Mb/s, B 46.1 Mb/s | A 77.7 Mb/s, B 46.1 Mb/s or more (TC-CORE-11) |

### 7.2 Packet ports

| Port | Rate | Bytes per beat | Overhead per packet | Evidence |
| --- | --- | --- | --- | --- |
| `S_Pkt` | One beat per `UserClk` cycle while the transmit FIFO has room | One byte in a beat with `TLast` = '0'; the marker beat carries none | One beat (the end of packet marker) | TC-DL-43 |
| `M_Pkt` | One beat per `UserClk` cycle while the receive FIFO holds N-Chars | One byte in a beat with `TLast` = '0'; the marker beat carries none | One beat (the end of packet marker) | TC-DL-43 |

The core passes the bytes of a packet unchanged: n bytes are n + 1 beats at the packet ports of both ends. The
length of a packet is not limited: the FIFOs hold N-Chars, not packets, and nothing counts the bytes of a packet;
packets of up to 65542 bytes are simulated, also with a link error in the middle (TC-CORE-17, TC-CORE-18). Over time
a packet port carries at most the rate of the link; to keep up with it, `UserClk` needs at least R / 10 cycles per
second, one cycle per N-Char of 10 bit periods.

### 7.3 Latency

| Item | Value |
| --- | --- |
| Received character | Passed two bit periods after its last bit (parity check of the next character), plus the crossing of the receive FIFO |

## 8. Integration constraints

| Constraint | Reason |
| --- | --- |
| `LinkClkFreq_g` equals the frequency of `LinkClk` | The initial data signalling rate, the disconnect time, the 6.4 us and 12.8 us timers of the link state machine and the interrupt tick are derived from it (ECSS 5.4.8, 5.4.10, 5.5.7) |
| `LinkClkFreq_g` lies in 18 to 22 MHz, 27 to 33 MHz, 36 to 44 MHz or 45 to 2554 MHz; elaboration stops otherwise | 10 Mb/s +/- 10 % from an integer divider (ECSS 5.4.10); reception of the initial rate of the far end with 1.2 `LinkClk` periods per bit; the 8-bit field LINK_SPEED.INIT_DIV (section 2) |
| The bit period of the far end, reduced by its skew and jitter, is longer than one `LinkClk` period; LINK_SPEED.RUN_DIV is set so that the port does not send faster than the far end can receive | The receiver samples data and strobe once per `LinkClk` period (section 3); SpaceWire has no negotiation of the data signalling rate |
| LVDS output buffers for data and strobe (TIA-644-A), or LVTTL inside a unit | ECSS 5.3.6.2, 5.3.6.3; the core contains no I/O buffer |
| LVDS input buffers with fail-safe biasing for data and strobe | ECSS 5.3.6.2.5: an unpowered driver, an open or a shorted line must not produce edges at the receiver output |
| Output flip-flops of `Spw_DOut` and `Spw_SOut` placed in the I/O blocks, matched routing of data and strobe | Small output skew DSskewOUT (ECSS 5.3.7.2g) |
| `set_false_path` from `Spw_DIn`, `Spw_SIn` and `Rst`; `set_max_delay -datapath_only` with the period of the faster clock between each pair of `LinkClk`, `UserClk` and `MgmtClk` (no asynchronous clock groups) | The inputs and the reset enter synchronisers; every crossing between the clocks is an Open Logic entity with triplicated synchronisers |
| TMR of the synthesis tool enabled for the core | The core protects its FIFO buffers and synchronisers itself and relies on TMR for all other logic (section 5) |
| Safe implementation of state machines enabled in the synthesis tool | Keeps the `when others` recovery of the state machines (section 5) |
| INT_HOLDOFF and INT_ACK_DELAY set for the network before distributed interrupts are used | Both are zero after reset and depend on the propagation through the network (ECSS 5.6.5.4c, d, 5.6.5.6e; section 4.2) |
| `M_Pkt_*` is served | The port gives credit only for free places of the receive FIFO (ECSS 5.5.4): a receive port that is not served stops the traffic of the far end on this link |
| The indication ports `M_Tc_*`, `M_Int_*` and `M_IntAck_*` are served before the indication FIFO (16 entries) fills | An indication that finds the FIFO full is discarded and sets EVENTS.IND_OVERFLOW |
| Registers are written as 32-bit words; a read that depends on a write waits for the write response | The register file ignores byte enables; AXI4-Lite does not order a read against an earlier write (section 4.3) |

## 9. Conformance

OpenWire implements a SpaceWire port of a node with one end-point according to ECSS-E-ST-50-12C Rev.1; the functions of
a routing switch are not part of the core. The [compliance matrix](compliance.md) lists the requirements and the test
cases of every clause. Where the standard leaves a choice, the section "Interpretation of the standard" of the module
specifications ([owr_encoding](../hdl/owr_encoding/docs/specification.md),
[owr_data_link](../hdl/owr_data_link/docs/specification.md), [owr_network](../hdl/owr_network/docs/specification.md))
states the behaviour of the core.

| Status | Clauses | Scope |
| --- | --- | --- |
| Implemented | 5.2.1 to 5.2.8, 5.3.8, 5.4.2 to 5.4.11, 5.5.2 to 5.5.7.7, 5.5.8, 5.5.9, 5.6.2, 5.6.3, 5.6.4.1 to 5.6.4.5, 5.6.4.8, 5.6.4.9, 5.6.5.1 to 5.6.5.4, 5.6.5.6, 5.6.6, 5.6.7, 6.1 to 6.5 | Encoding layer, Data Link layer, Network layer of a node, MIB of a node and the service interfaces. Time-codes and distributed interrupts are options of the standard (ECSS 5.6.4.1a, 5.6.5.1a), selected by `TimeCodes_g` and `Interrupts_g`; the distributed interrupts support the interrupt mode and the interrupt with acknowledgement mode |
| Partially implemented | 5.3.6, 5.3.7 | The core drives and receives the data and strobe signals and the enables of the line drivers and receivers, and tolerates the receive skew of section 4.4. The electrical properties of the line drivers and receivers and the output skew are properties of the target (section 8) |
| Partially implemented | 5.6.10 | 5.6.10f, port loopback (PORT_CTRL.LOOPBACK). 5.6.10a to e describe a network |
| Partially implemented | 5.7 | 5.7.2a, b, 5.7.3 to 5.7.5 and 5.7.6a (parameters of a node). 5.7.2c, d and 5.7.6b concern routing switches |
| Not implemented | 5.3.2 to 5.3.5 | Cables, connectors, cable assemblies and PCB tracks: properties of the board and the harness |
| Not implemented | 5.5.7.8 | Alternative behaviour when LinkDisabled is asserted: a permission for devices of the previous issue of the standard |
| Not implemented | 5.6.4.6, 5.6.4.7, 5.6.5.5, 5.6.5.7, 5.6.8, 5.6.9 | Routing switch: time-code and interrupt relaying, routing, management parameters of a routing switch |

## 10. Corrected defects

| Defect | Affected | Effect | Correction |
| --- | --- | --- | --- |
| `RxFifoDepth_g` below 16 and FIFO depths above 32768 were accepted | All versions before the generic range checks | With `RxFifoDepth_g` = 8 the port never sends an FCT, so the far end never sends data to it; with a depth of 65536 the 16-bit fields FIFO_DEPTHS and FIFO_LEVELS read the depth and a full FIFO as 0 | The elaboration stops outside `RxFifoDepth_g` 16 to 32768 and `TxFifoDepth_g` 2 to 32768 (section 2) |
| `LinkClkFreq_g` of 2555 MHz or more was accepted | All versions before the generic range checks | LINK_SPEED.INIT_DIV read 0 for `LinkClkFreq_g` of 2555 MHz or more; no realistic configuration is affected | The elaboration stops at 2555 MHz and above (section 2) |
| `LinkClkFreq_g` of 9 to 11 MHz was accepted | All versions before the generic range checks | The receiver cannot sample the initial rate of the far end (up to 11 Mb/s), so the link does not start | The elaboration stops below 13.2 MHz (section 2) |

## 11. Verification and checks

```shell
python run.py -p 8                  # regression with GHDL
python run.py --questa -p 1             # regression with QuestaSim, full optimisation
python run.py --questa --coverage -p 1  # regression with QuestaSim and code coverage (coverage.md)

python tools/compliance.py --check  # ECSS traceability
```
